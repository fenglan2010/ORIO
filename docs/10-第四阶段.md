# 第四阶段

第四阶段要让系统开始沉淀可复查的决策经验，并在可靠之后以匿名方式引用同类酒店的模式。本文件按增量记录已交付范围。**第一增量（本店 Memory Node / 本店经验沉淀）已交付。第二增量（L5 匿名跨店学习 / 匿名行业模式）已交付。知识图谱、强化学习、一键迁移策略、结果归因尚未开始。**

## 第一增量：本店 Memory Node（已交付）

- 工作流在 `execution_node` 之后进入 `memory_node`，再结束。人审否决（或其他终态处置，例如回滚）也会进入 `memory_node`，以便把拒绝结论记下来。仍在等待人审、或已通过但尚未执行时，不写记忆行。
- LangGraph 与等价状态机走同一条节点路径、同一套节点函数。`engine_info()` 把 `memory_node` 列入 `nodes`，`reserved_nodes` 为空。
- 记忆只按 `hotel_id` 读写。杭州演示店（`tenant_key=demo`）与成都演示店（`tenant_key=demo_chengdu`）的记忆互不可见，也不会在下一轮运行中互相引用。
- 表 `memory_records` 在原有结构上补齐查询字段：`run_id`、`strategy_id`、`checkpoint_id`、`approval_status`、`action_kind`（`pricing` / `campaign` / `review_reply`）、`risk_level`、`episode_key`。新行的 `kind` 为 `decision_episode`。`payload` 只记录已有事实：建议摘要、风险、操作者、审批结论、沙盒回执或拒绝结果、写入任务状态、检查点、日期与房型。结果影响字段仅预留钩子，默认 `outcome=not_measured`、`impact=null`，**不编造同比、准确率或「这次调价带来了多少收入」**。「这次调价实际带来了什么」仍是推迟的产品项，本增量不实现归因。
- 同一策略（或同一 `run + strategy + 终态`）只写一行，重跑或回放不会重复插入。
- 新一轮运行会加载**本店**近期记忆到状态（`historical_memories`，并据此诚实填充 `historical_strategies`）。分析节点与策略节点可将其引用为「本店近期已执行 / 已否决」上下文。存在记忆不会改变执行策略，也不会跳过人审或自动改价。
- `GET /api/memories`：需登录，权限沿用 L5 已有的 `view_l5`，只返回当前酒店记录，最新在前，支持 `limit` / `offset`。非本店成员为 403 或看不到该店数据。本增量不提供酒店用户侧的写入或删除学习引擎接口。
- L5 页展示本店经验沉淀列表，不再使用「进化事件日志（示意）」假数据。转化率曲线仍使用本店近 14 日实际指标。跨系统迁移、进化引擎开关、发明新策略、进入沙盒模式保持不可用。时间线节点文案为「经验沉淀」，去掉「预留」。
- 演示默认不变：`auto_execute_enabled=false`、`write_mode=sandbox`，不预装生产官方契约，不编造携程 / 美团 / 飞猪生产 URL。酒店设置页仍不展示模型路由、适配器、境外开关或密钥。

## 第二增量：匿名跨店学习（已交付）

- 本店终态决策写入 `memory_records` 时，同时向上插入一条**匿名行业模式**（表 `industry_patterns`）。模式键只哈希去标识特征：动作类型、已有信号类型、风险等级、终态分桶（已执行 / 已否决 / 已回滚 / 执行失败 / 部分执行）、以及在已有事实时的价格方向（涨 / 降 / 不变，不含金额）。定位分桶（如「精品」「商务」）仅在同模式的其他酒店可共享时用于展示，不写入模式键，也不保存城市或酒店名。
- 贡献关系写在私有表 `industry_pattern_contributions`，仅用于 k 匿名与自排除计数，**酒店用户侧接口永不返回酒店 id 或贡献名单**。同一本店 episode（同一 `episode_key`）不会重复计数。
- 可见性：只有至少两家酒店贡献了同一模式时，才作为「行业模式」展示；当前酒店看到的计数排除本店身份。仅一家酒店拥有的模式，既不展示给其他酒店，也不对本店伪装成同行经验。因此杭州在成都也有匹配 episode 后可以看到该模式，反之亦然。
- 可识别数据不得跨店：`GET /api/memories`、`memory_records` 行，以及新一轮运行的 `historical_memories` / `historical_strategies` 仍严格限于本店。跨店学习只通过单独的状态字段 `peer_patterns`（同时写入 `industry_patterns` 别名）提供匿名聚合。
- 分析节点与策略节点可将可见模式引用为「同类酒店在类似信号下曾执行 / 否决类似动作」。存在行业模式不会改变执行策略，不会跳过人审，也不会打开自动执行或线上写入。
- `GET /api/memories/patterns`：需登录且具备 `view_l5`，只返回当前酒店可见的匿名模式，按同行片段数、最近贡献时间排序。响应不含酒店 id / 名称、`tenant_key`、地址、城市、精确价格、房型名、评价原文、客人个人信息、检查点 id、策略 id 或其他酒店的操作者姓名。默认 `outcome=not_measured`，不编造同比、准确率或收入提升。
- L5 页新增「匿名行业模式 / 跨店学习」列表，保留本店经验沉淀和近 14 日本店转化率。文案明确：跨店学习已开始，但是匿名模式，不展示其他酒店名称，不会训练模型，不会自动改价。跨系统迁移、进化引擎、发明新策略、进入沙盒模式仍然不可用；一键迁移不开放，以免带出其他酒店身份。跨店学习是匿名模式引用，不是复制其他酒店的在用策略。
- 本增量不实现知识图谱、强化学习、效果归因，也不在酒店设置页增加模型路由或贡献开关。默认仍是每家酒店只贡献匿名特征，自动执行关闭，写入模式为沙盒，不预装生产契约，不编造官方生产 URL。

## 本增量未包含（留给后续增量，尚未开始）

- 一键迁移策略，或其他会带出酒店身份的跨店复制
- 「这次调价实际带来了什么」的结果归因（仅留下 `outcome` / `impact` 钩子）
- 官方生产契约就位后的真实 OTA 写入、官方 PMS/CRS、可单独售卖的轻量 PMS
